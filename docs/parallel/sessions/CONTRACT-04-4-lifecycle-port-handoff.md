# CONTRACT-04-4: Track E hand-off — what the lifecycle sends to `ExecutionPort`, additive fields, and the shared conformance test

- **Requester:** Session 04 (Phase 2 completion) · **Addressee:** Session 05 (builder lifecycle), via the Master · Status: PROPOSED (additive; nothing breaks if S05 does not adopt it yet)
- **The traffic (read from `agent-tools/builder/execution-build-port.ts` and `repair.ts`):** per build/test call for `typecheck`, `unit-tests`, `build` only: `port.request({orgId, runId, profile})` (preflight, nothing runs), then `d = port.request(...)` and `port.run(d, {orgId, runId})` with the SAME decision object; `completed` + non-zero exit → failed; artifacts without `sha256` dropped; logs = stdout + stderr; one call per profile per repair round, through one port bound to the run. `install-deps` and `run-script` are never requested by the loop. The same text is data in `executionGateway.LIFECYCLE_PORT_CALLS`.
- **Additive fields in `packages/domain/src/ai/execution-gateway/port.ts` (mine, already committed):**
  1. `ExecutionRunContext.source?: { projectId; versionId }` — which project version the run is for. **S05 must pass it** (`port.run(decision, { orgId, runId, source: { projectId: req.projectId, versionId: req.versionId } })`) because the repair loop builds a NEW version each round and a real port seeds the workspace from it; the mock ignores it. Today's `ExecutionBuildPort.build` does not pass it: the shared test reports that case (H-9) SKIPPED with this reason, and FAILS under `expectSource: true`.
  2. `ExecutionOutcome.usage?: { cpuSeconds, peakMemoryMb, peakPids, diskMb }` — what the runtime measured; the orchestrator settles quota on it when present. No consumer change needed.
  3. `ExecutionOutcome.artifacts[].kind?` (added earlier, CONTRACT for O-13): unchanged.
- **Composition-root requirement (not in S05's adapter):** the real port is `RealRuntimeService.portFor(execContext, { seedFiles: (source) => …, canaries })`; `seedFiles` must read the project's files **at `source.versionId`** from `ProjectsPort`. The port refuses a workspace seed containing secret files, directories or canaries.
- **The shared conformance test (both sides run it):** `executionGateway.runLifecycleHandoffConformance(rigFactory, { expectSource })` with 9 cases (preflight allowed/refused, a repair round with the fixed argv per profile, timeout, non-zero exit, foreign run/org refused, no leftovers between calls, artifact policy, source reaches the port). A rig is `createMockHandoffRig(adapt)` or `createSimulatedNodeHandoffRig(adapt, pump?)`; `adapt` is `(port) => new ExecutionBuildPort(port, now)` — i.e. S05 runs it with their own adapter; Session 04 runs it with the same adapter in `real-runtime/handoff-conformance.spec.ts`. After D-21 the live rig is added to the same test. Every report says SIMULATED: it proves wiring and policy, not isolation.
- **Where to run it on S05's side:** a spec in `packages/domain/src/ai/agent-tools/builder/` (their path) importing `executionGateway` from `../../execution-gateway` and calling `runLifecycleHandoffConformance` for both rigs; set `expectSource: true` once the adapter passes `source`.
- **Tests added (mine):** `handoff-conformance.spec.ts` (4 tests, all pass with S05's real adapter over the mock and the simulated node; the strict-source case fails for today's adapter and passes for one that names the version).
