# CONTRACT-S05-P2-3 — inference cost and execution cost are separate gates

- Requester: Session 05 (Phase 2) · Contracts touched: billing seed data (Master), the sandbox service (Session 04) · Status: PARTLY ACCEPTED 2026-11-24 (Master): item 3 (docs/12 wording) applied; item 1 (billing seed row and entitlements) DEFERRED: the limits are an owner price decision (HG-02-01), recorded as row BILL-SEP in `OWNER-APPROVAL-PACK.md`; the switch stays OFF; item 2 (S04 `purpose` parameter) assigned to S04. Default behaviour is UNCHANGED (switch off).
- Finding, design and evidence: REPORT-05 "Phase 2" §"Release build needs AI wallet credit". Summary: `SandboxService.create` refuses with `budget_required` when the AI wallet is empty, so a release build of an app no model touched needed AI credit. Execution work is now gated by the plan's build allowance and the platform ceilings; inference stays gated by the wallet through the model gateway (ADR-061). Nothing becomes free: execution is still hard-gated and always metered.

## What I implemented (my paths, behind `builder.billing_separation`, default OFF = today)
- Pure policy `builderTools.lifecycle.decideExecutionStart` (both settings tested), `ExecutionGate` / `ExecutionBudgetService` / `ReleaseBuildBudget` (`appbuilder/internal/lifecycle/execution-budget.service.ts`).
- A SECOND `SandboxService` instance (`RELEASE_BUILD_SANDBOX`, same runtime, same database, same concurrency limit) whose budget port is `ReleaseBuildBudget`; only `AppDeploymentService` (the release build) uses it. No file under `appbuilder/internal/sandbox/**` (Session 04's) was edited.
- Switch OFF: the release build asks exactly what it asked before (AI credit > 0). Switch ON: residency, the platform ceilings and the BUILD ALLOWANCE (quota group `builder`), and the AI wallet is not asked.

## Requests
1. **Master (billing seed data), needed before the switch can mean anything in production:** a row in `billing.quota_meters`: `('builder', 'builder.build_minutes')` and plan entitlements (`meter_limit`, group `builder`, mode `hard`) with the limits the owner sets (HG-02-01). While the row is absent the group is reported as UNMEASURED (`QuotaService.check` → `measured: false`): the gate then admits ONLY because the platform ceilings (5 concurrent sandboxes per organization, 4 h lifetime, cpu quota) still bound it and the metering is mandatory, and it audits `build_allowance_unmeasured`. An organization on such a plan therefore has no monthly build cap until the row exists: **do not switch `builder.billing_separation` on for an organization before the entitlement exists.** No migration is needed from me; this is data in the billing schema (Master-owned).
2. **Session 04 (sandbox owner), cleanup, not blocking:** give `SandboxService.create` an explicit `purpose` (`release_build | user_sandbox | ai_run_build`) so the gate is chosen by the caller instead of by which instance was injected, and fix the message: `budget_required` currently says "the organization has no AI credit left for a sandbox" even when the refusing gate is the build allowance. The HTTP `POST …/sandboxes` path (a user starting a sandbox) still checks the AI wallet; it is the same finding for a user sandbox and can move to the same gate with the same switch.
3. **docs/12 §7 (Master):** the table row "AI gateway/sandbox start | per-request budget check against `ai` budgets and credits | hard" should read: AI gateway → `ai` budgets and credits; sandbox/build start → build allowance (`builder.build_minutes`, included meter) and platform ceilings; both hard.

## Metering (no unmetered usage)
- A REAL execution emits `builder.build_minutes` (quantity = minutes, idempotent: the event id derives from run, phase, repair round, profile and the step attempt's start time) through `emitUsage`; the existing sandbox cpu metering (`ai.sandbox_cpu_seconds`) is unchanged. The release build path already emitted `builder.build_minutes`.
- A SIMULATED execution (the mock Execution Gateway port) is NOT usage: nothing ran, nothing is billed; it is audited (`builder.execution.simulated`, `billed: false`) and every result says `simulated`.
