## C. Implemented features
1. **Node protocol** (`POST /v1/<op>`, 15 operations): strict total parsing (unknown member/type/size refused, workspace paths normalised), `wait` in 25 s slices. **Request token**: Ed25519, ≤ 60 s, bound to node, operation, exact body hash, scope (admin ops), organization, workspace and handle; one-time id with a fail-closed replay cache. mTLS transport (TLS 1.3, one pinned CA, optional leaf pin, no redirects, size caps).
2. **Node agent**: config that fails closed (no wildcard listener, simulated launcher only on loopback, real launcher requires XFS project quota, pinned client fingerprints, public keys only); image tree digests recomputed at start (mismatch = refuse to start); second-line spec validation on top of `validateRuntimeSpec` (node runtime class, constant env, sandbox uid, node ceilings, attested image only, egress allow-list, cwd, mounts); tenant binding from the token; capacity and one-run-per-workspace; wall-clock backstop and a resource monitor (a run whose statistics cannot be read five times is killed); output flood killed; leaked-cleanup tracking (node unhealthy until reaped); `emergencyStop` (node-local `DISABLED` flag, kills everything, destroys every workspace); reaper for aged workspaces, strays and half-created directories; restart recovery; content-free audit + Prometheus metrics (loopback listener).
3. **gVisor launcher** (`runsc-launcher.ts`, `oci.ts`, `network.ts`): OCI bundle (read-only root, no capabilities in any set, `noNewPrivileges`, five namespaces, cgroup v2 memory/swap=limit/cpu/pids, rlimits, masked paths, default-deny seccomp allow-list with a never-list test, `clone` without namespace flags, `clone3`→ENOSYS), per-sandbox veth /30 with one /32 route to the proxy and no default route, `runsc run/kill/delete/events/list` argv, XFS project quota commands, cleanup that THROWS if anything remains.
4. **Egress proxy** (`egress-proxy.ts`): CONNECT-only, exact host allow-list, port 443 only, every DNS answer must be public (private/loopback/link-local/CGNAT/documentation/multicast/mapped/embedded forms refused), connects to the vetted IP, tunnel caps/timeouts. Static nftables ruleset: default-deny in input/forward/output, nothing forwarded, sandboxes reach one socket (the proxy), metadata dropped.
5. **Real `ExecutionPort`**: `startRealExecution` (vault references → `VaultTokenSigner` + mTLS → `RemoteWorkspaceRuntime` → `RealRuntimeService`), fail-closed. `RemoteWorkspaceRuntime` is `WorkspaceRuntime`; isolation is never read from the node and a loopback transport can never claim `verified`.
6. **Durable stores**: schema `execution`, nine tables, migrations 2310–2312 with documented reversal; SQL transition guards mirror the domain's; append-only history, single-use approvals (one atomic UPDATE), kill-switch history, usage records (money in integer minor units), RLS forced; `PgExecutionStore` (idempotent enqueue, fair atomic claim, leases and sweep, approvals, kill switch, workspaces, reservations, usage, node and attestation records).
7. **Qualification tooling** (`qualification.cli.ts`): `conformance` (S10, labelled NOT VERIFIED against a real node, SIMULATED over loopback), `sign` (S13, refuses to sign over an escape/incomplete set, verifies its own output live), `negative` (S14, nine refusal cases + positive control), `evidence` (S15, append-only index with cross-checks); the escape-suite CLI now connects to https endpoints with vault references from a private directory outside the repo.
8. **Recipes and ops**: rootfs recipe/script (pinned snapshot, checksummed Node, lockfile-only toolchain, no package manager/compiler/network client/git), npm mirror config, install script, alerts (17 rules; names and runbook anchors checked by a test) and the runbook, control-plane runtime metrics.
9. **Android build environment** for P3-S06: definition + validator + plan-first build script + hand-off README; the shipped file is refused by the validator until pins and a named licence acceptor exist.
No HTTP API, UI screen or feature flag was added (nothing here is reachable from a route; `ai.agent.exec_tools` stays off and the gate closed).

## F. Security, tenant isolation, billing, residency verification
- **Tenant isolation (SIMULATED):** a token for organization B is refused (403) on every operation against organization A's workspace/run, including `kill`; tokens without an organization can only clean up; a spec for another run or organization is refused; RLS on all tenant tables proven through the runtime role.
- **Spec second line (SIMULATED):** 15 weak-spec cases (privileged, host namespaces, writable root, root user, runc class, extra env, preload variable, docker-socket mount, swap, cwd escape …) plus node ceilings, unlisted egress host and unattested image are refused by the agent before any launcher call.
- **R5 (structural, SIMULATED/static):** `NodeCommandRunner` is the only process door; it refuses off Linux, without an identity file naming the node and the right runtime class, for any binary outside a fixed absolute-path list, with a scrubbed environment and no shell; every test uses a recording runner or a simulated launcher; a static test fails if any S02-owned production file imports `child_process`/`vm`/`worker_threads`; `assembleAgent` on a non-Linux platform throws `AgentStartRefused`; `startRealExecution` refuses with no node, no attestation, an attestation of the wrong label, or an unreachable node. See finding A for pre-existing opt-in dev runners elsewhere.
- **Billing:** nothing bills. The usage record is the fact handed to the metering pipeline (`billed` flips once); reservations are holds; no ledger row is written (CLAUDE.md §4).
- **Residency (GAP):** tables carry `data_region`, but **no `ResidencyPolicyService` call exists before a real run is placed on a node, and nodes have no region in the registry**. Acceptable only while data is synthetic (D1); must be wired before any customer data (orchestrator-side, behind the flag). Recorded in the hook registry note (CONTRACT-2).
- **Secrets:** vault references only; inline PEM/paths refused; the qualification host resolver refuses a directory inside the repo or readable by others; `sign` refuses a reviewer key inside the repo or readable by others; the agent config holds paths and public keys only; evidence index flags private-key markers.
- **Isolation itself: NOT VERIFIED.** gVisor flags, the `events`/`list` formats, seccomp compatibility with `npm`/`tsc`/`build`, the XFS quota report format, cgroup delegation and the firewall are all unrun.
