## F. Security, tenant isolation, billing, residency verification
- **Tenant isolation:** RLS-forced org tables; org B reads 0 rows from every hosting org table via the app role and cannot insert for org A; HTTP: another org's site, domains, certificates, databases, backups, download link, abuse case → **404**; node data (nodes, capacity, agents, allocations, command log) unreadable in org scope (0 rows). Staff cross-org reads are audited (`hosting.admin.cross_org_read`).
- **Agent channel:** unsigned/forged/expired/future/replayed(+after restart)/foreign-node/oversize/malformed envelopes and 9 non-allow-listed names rejected; 13 injection payloads and 10 malformed `site.create` argument sets rejected; token reuse with different arguments rejected; audit chain tamper-evident. **Mock only.**
- **Secrets:** vault refs only; site credentials, backup keys and custom certificate keys never appear in tables, audit, outbox, idempotency rows, operations or responses (scan test); download links are HMAC-bound to org/site/backup and expire.
- **Billing/metering:** meters `hosting.site_months|disk_gb_months|bandwidth_gb|backup_gb_months` through `emitUsage`; deterministic ids; replay 0 diff; hosting quote priced from the price book (placeholder plan prices never quoted); order/authorization via the M02 `OrderService`; dunning suspension against real `billing.dunning_cases`.
- **Residency:** placement only in regions the org policy allows (M04 `ResidencyService`, hook `m06-node-selection` **enforced**); backup region = site region with a residency check (`m06-backup-sink` **enforced** too (call site `backups.service.ts` calls `assertResidency`); the registry flags `residency.enforce.hosting*` are the owner's switch (see I)); migration never crosses regions.
- **Money/idempotency/durability:** no floats (integer minor units, exact decimals); `Idempotency-Key` on side-effecting POSTs; long work = `platform.operations`; after an uncertain result → `findByToken` before any retry.
