## 2. Where M09's proposal and the M11 prompt differ (recorded, not reconciled silently — CLAUDE.md §2)
1. **Event topics.** docs/05 §5 and the M11 prompt allow-list `ai.run.completed` and `site.deployed`; M09's contract plans `ai.run.<state>` / `deployment.<state>`. M11's allow-list is the docs/05 set (higher source). **Open decision:** extend the allow-list (and `spec/events/`) when M09 publishes its topic names; the allow-list is one constant (`ALLOWED_EVENT_TOPICS`, `apps/api/src/modules/automation/internal/model.ts`, mirrored in `apps/worker/src/automation-consumers.ts`).
2. **Run kinds.** M09 supports `website|edit|chat` now and answers `422 unsupported_kind` for `webapp|mobile|test-fix` until M10: a workflow step with such a kind will fail with the port's error (non-retryable). The workflow validator accepts the docs/04 kinds.
3. **Approvals.** An M09 run can stop at `waiting_approval` (human approval of publish/delete/spend). The M11 action returns `{runId, status}` after START and does not wait: a workflow that needs the result must listen to the run's completion event (once its topic is allow-listed).
4. **Feature flags.** M09's `ai.enabled` gates its routes; M11 adds its own flags (`automation.enabled`, `marketplace.enabled`, `agency.enabled`, `reseller.enabled`, all default OFF). A workflow AI action needs both.
5. **Recursion/chain depth.** M11 refuses chains deeper than `AUTOMATION_MAX_CHAIN_DEPTH` (default 5) using an `automationDepth` field in the event payload. M09 does not set it yet: until it does, the self-trigger backstop is the per-workflow execution-spike rule (auto-pause) and the static check at trigger registration.
6. **Credits.** M09 settles AI cost on the wallet per call (`usageChargeWallet`) and notes the double-billing risk of `ai.credits_consumed`. M11 meters only `automation.executions` and `automation.steps`; AI cost is M09's (the `start_ai_run` step counts as one billable step).

## 3. Other upstream assumptions
- **M10:** website templates only are installable (app templates answer the same port error). The artifact format of a website template is whatever M09's `site_model` import accepts: **not defined yet**; M11's scanner treats a template artifact as a JSON object with an optional `package.json` member.
- **M04:** consent/residency/DSR. Residency is called through `ResidencyService.evaluate` (enforced hooks `m11-connectors`, `m11-marketplace`). Consent capture for marketing is unnecessary today because M08 blocks marketing email. **DSR erase/export of execution inputs and webhook payloads is NOT implemented** (see M11-report §G).
- **M05/M08:** metering meters `automation.executions`/`automation.steps` already exist in the catalogue (migration 0201); the quota group `automation` is mapped by M11's migration 1606 with no limit (limits are HG-02-01).
