# @nuzm/adapter-alibaba-ecs

`ComputeAdapter` (contract 1.0.0) for Alibaba Cloud ECS (RPC API `2014-05-26`) with BSS billing (`2017-12-14`). Built only from Alibaba's published documentation; **every result is NOT VERIFIED** — no Alibaba account, RAM user or credential exists (HG-05-01 PENDING) and no call to Alibaba was ever made. Saudi Arabia appears in the documentation (`me-central-1`, "SAU (Riyadh - Partner Region)") — that is documentation, **not** proof the account can use it: the region is `verified` only from live evidence in the account's own `DescribeRegions` listing.

## How the contract is met

| Contract                   | Alibaba mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `probe` (side-effect free) | `DescribeRegions` (auth), `DescribeInstances` (→ `inspect`), the same with a `Tag` filter (→ `find-by-token`), `DescribePrice` (→ `quote-api`), `DescribeInstanceBill` (→ `billing-export`). Mutating capabilities are proven with **`DryRun=true` against an existing instance of the account** (`StartInstance`, `StopInstance`, `RebootInstance`, `ModifyInstanceSpec`, `DeleteInstance`) and `RunInstances` DryRun (needs an image, an in-stock type and configured VPC networking). Only the documented success signal `DryRunOperation` ⇒ `supported`; `Forbidden*` ⇒ `unsupported`; anything else, and every capability whose proof would need an existing instance when the account has none, ⇒ `unknown` (= unsupported). `CreateSnapshot` has no documented DryRun ⇒ `unknown` until a live run proves it. `DescribeInstanceMonitorData` read ⇒ `metrics`. |
| idempotent provision       | `ClientToken` = the 64-hex idempotency token (the vendor dedupes)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `findByToken`              | `ClientToken` is not queryable, so instances carry the tag `nuzm-token=<token>` (and `nuzm-org=<opaque org hash>`); lookup = `DescribeInstances` with the tag filter over every listed region (or the region this process provisioned in). A region that cannot be searched ⇒ `failed`, never `data:null`. Describe-after-write visibility is **NOT DOCUMENTED** — absence is only proof if the listing is read-your-writes (to be established live)                                                                                                                                                                                                                                                                                                                                                                                                                 |
| timeouts                   | a timeout, connection error, HTTP 500/503 on a mutating call ⇒ `uncertain`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `delete`                   | `DeleteInstance Force=true` (docs: `Force=false` requires Stopped); `InvalidInstanceId.NotFound` ⇒ already gone ⇒ `succeeded`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `resize`                   | `ModifyInstanceSpec`; the docs require the instance **Stopped**, so a running instance gets `conflict` (the orchestrator stops it first)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `snapshot`                 | `DescribeDisks(InstanceId, DiskType=system)` → `CreateSnapshot(DiskId)`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| prices                     | `DescribePrice` returns major-unit numbers; minor units are **NOT DOCUMENTED**. 2 minor digits are assumed (ISO 4217 for CNY/USD), hourly price rounded **up** (`toMinorUnits`, BigInt, no float artefacts). `TradePrice` of instance + 40 GiB `cloud_essd` system disk; bandwidth/IP are not in the price (`InternetMaxBandwidthOut` default 5 Mbit/s, `PayByTraffic` default ⇒ egress cost is **not metered**: row NOT VERIFIED)                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| billing                    | `DescribeInstanceBill` (`ProductCode=ecs`), `Items` accepted as array or `Items.Item[]` (the docs show both across pages), `PretaxAmount` rounded to 2 decimals, `providerRef` = bare instance id                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

Not provided by the documentation (so not done): VPC/VSwitch/security-group creation (APIs not read) — networking is **configuration** (`network(regionId)`), without it provisioning is `unsupported` there; Windows images (key pairs are Linux-only); multiple SSH keys (one `KeyPairName`); an error-body schema (`Code`/`Message` are read defensively and the HTTP status is the fallback); `DescribeInstanceTypeFamilies`, CloudMonitor, `DescribeSnapshots` (not read); the BSS endpoint a Riyadh-region account must use (Singapore endpoint is the documented default for the international site; Riyadh is not on the BSS endpoint page).

## Least-privilege RAM user (as documented)

`ecs:DescribeImages`, `ecs:DescribePrice`, `ecs:DescribeInstances`, `ecs:DescribeInstanceAttribute`, `ecs:DescribeInstanceStatus`, `ecs:DescribeDisks`, `ecs:DescribeInstanceMonitorData`, `ecs:RunInstances` **plus the dependent actions the RunInstances page lists** (`vpc:IsDefaultVSwitch`, `vpc:IsDefaultVpc`, `vpc:VPC`, `vpc:CreateDefaultVpc`, `ecs:InstanceType`, `ecs:ImageOwnerId`, …; the page says all are required; whether a plain call needs them all is NOT DOCUMENTED), `ecs:StartInstance`, `ecs:StopInstance`, `ecs:RebootInstance`, `ecs:ModifyInstanceSpec` (+ `ecs:AssociatePublicIpAddress`), `ecs:DeleteInstance`, `ecs:CreateSnapshot`, `ecs:ImportKeyPair`, and for billing `bssapi:DescribeInstanceBill` (the docs use both `bssapi:` and `bss:` prefixes across BSS pages). `DescribeRegions`/`DescribeZones`/`DescribeAvailableResource`/`DescribeInstanceTypes` say "no authorization required" and have no RAM action. Resource scoping: a dedicated resource group/tag is advisable but not documented as enforceable per action.

## Documented limits honoured

`RunInstances` 100/60, `DescribePrice` 500/60, Start/Stop/Delete 500/60, others 1000–2000/60 (metadata, unit inferred); BSS 10 req/s. Throttle codes `Throttling*` ⇒ `rate_limit` (retryable). HTTP statuses for the same code differ between pages, so classification keys on the **code** first.

## Egress and credentials

`*.aliyuncs.com` (https only; SSRF guard in `@nuzm/adapter-http`), see `spec/providers/providers.yaml`. Vault fields `accessKeyId`, `accessKeySecret`. Keys are never logged; the framework redactor registers both values and their base64/URL forms.

## Tests

`pnpm --filter @nuzm/adapter-alibaba-ecs test`: signer vs the documented worked example; conformance kit (15 cases) against `AlibabaSim` (a local server that verifies the V3 signature and answers documented shapes; fixture evidence, `liveStatus: NOT VERIFIED`) — the simulated RAM user may not call `ModifyInstanceSpec` in the kit run because the kit resizes a _running_ instance, which ECS refuses; resize is covered by its own spec (stop first). ## S04: first-boot configuration (`UserData`) for a Hestia VPS

`ProvisionRequest.userData` (cloud-init text) is sent as `UserData`, **Base64-encoded** as documented ("The data must be Base64-encoded. The size of instance user data cannot exceed 32 KB before Base64 encoding", https://www.alibabacloud.com/help/en/ecs/developer-reference/api-ecs-2014-05-26-runinstances, read 2026-11-24). Linux user data runs through cloud-init, a script only once at first start, `#cloud-config` is supported; the image must be a public image (or one made from it) in a VPC — https://www.alibabacloud.com/help/en/ecs/user-guide/customize-the-initialization-configuration-for-an-instance. `listImages` carries `IsSupportCloudinit` (DescribeImages response/filter field) as `cloudInit`; an image without the statement is unknown = not usable for the bootstrap. Riyadh is `me-central-1`, "SAU (Riyadh - Partner Region)", zones A and B — https://www.alibabacloud.com/help/en/ecs/user-guide/regions-and-zones; https://sccc.sa/en/products/ecs does not state the region or its availability, so **access of a given SCCC account to `me-central-1` stays a live fact** (HG-05-05).

- `ClientToken` is the idempotency token; a replay with **changed** `UserData` is the vendor's `IdempotentParameterMismatch` (the simulator models it), which is why the bootstrap is a pure function of the order.
- This adapter's signer puts parameters in the query string (empty body), so `UserData` travels in the URL. The vendor ceiling is 32 KB, but the HTTP stack's URL limit is NOT DOCUMENTED, so the adapter refuses more than **8 KB before encoding** (`invalid_user_data`); the Hestia bootstrap is ~4 KB. Lifting this needs the body-parameter form of the V3 signature, read from the signature page and checked live.
- Alibaba warns not to put plaintext passwords or keys in `UserData`: the user data carries only the single-use, short-lived registration secret (stored server-side as a hash, bound to one order and one server, address-checked) and the customer's public SSH keys.
- `DescribeInstances` gives `PublicIpAddress.IpAddress`, `EipAddress.IpAddress` and the tags: the registration is matched against them.
