# @nuzm/adapter-huawei-ecs

`ComputeAdapter` (contract 1.0.0) for Huawei Cloud ECS. Built only from Huawei's published documentation; **every result is NOT VERIFIED** — no Huawei account, IAM user or credential exists (HG-05-02 PENDING) and no call to Huawei was ever made. `me-east-1` is documented as "ME-Riyadh" (API Explorer endpoint table and the Organizations "Regions for Using SCPs" page) — documentation, **not** proof the account can use it: a region is `verified` only from live evidence in the account's own IAM project list.

## How the contract is met

| Contract                   | Huawei mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| auth                       | vault fields `accessKey`+`secretKey` (AK/SK, recommended by the docs) **or** `iamUser`+`iamPassword`+`domainName` (token mode). In AK/SK mode the project id per region comes from `projectIds` (owner-recorded) or `GET /v3/projects?name=<region>` signed with AK/SK — **NOT DOCUMENTED** that IAM accepts AK/SK signatures for that call (token mode avoids the question)                                                                                                                                                                                                                                                          |
| `probe` (side-effect free) | reads only: server list (→ `inspect`, `find-by-token` via the documented `name` filter), flavors + BSS price (→ `quote-api`), BSS usage details (→ `billing-export`), CES query for an existing server (→ `metrics`). **Every mutating capability (`provision`, `delete`, start/stop/reboot/resize/snapshot) is `unknown` = unsupported** until a human-triggered live verification: no documented DryRun exists for them, and the Create `dry_run` flag is deliberately not used (a mis-honoured flag would create a billable server). `capabilityMode: 'documented'` exists for fixture runs only and is refused for live endpoints |
| idempotent provision       | V1.1 Create with `X-Client-Token` (UUID derived from our token). Because the window is 8 hours and servers cannot be looked up by client token, the token is **also** embedded in the server name `nz-<token>-<name>` and `server_tags` (`nuzm-token`, `nuzm-org`); `provision` looks the name up first and never creates when it exists                                                                                                                                                                                                                                                                                              |
| `findByToken`              | list servers with the documented fuzzy `name` filter, filter client-side by exact prefix, across the account's regions (the `tags=` filter syntax is NOT DOCUMENTED, so it is not used). An unsearchable region ⇒ `failed`, never `data:null`. List-after-create lag is NOT DOCUMENTED                                                                                                                                                                                                                                                                                                                                                |
| timeouts                   | timeout/connection error/HTTP 5xx/`Common.0001` on a mutating call ⇒ `uncertain`; HTTP 202 carrying an error body (`Common.0024`) ⇒ `failed` `rate_limit` (nothing was created)                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| async                      | create/start/stop/reboot/resize/delete are jobs ⇒ `accepted`; `delete` returns `succeeded` only if one check of the job already says `SUCCESS`. A `404` on a just-created id is ambiguous (docs: "being created, or creating failed") ⇒ `not_found`                                                                                                                                                                                                                                                                                                                                                                                   |
| `delete`                   | pre-check (404 ⇒ already gone), then `POST …/cloudservers/delete` with `delete_publicip` **and** `delete_volume` true (otherwise billable leftovers). Behaviour of deleting a missing server is NOT DOCUMENTED                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `resize`                   | V1.1 resize; the docs require the server **stopped** ⇒ `conflict` while running                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `snapshot`                 | boot volume (`os-extended-volumes:volumes_attached` with `bootIndex` 0) → EVS `cloudsnapshots`; the permission action for that call is NOT DOCUMENTED; the standard-snapshot API `v5` exists only in some regions                                                                                                                                                                                                                                                                                                                                                                                                                     |
| prices                     | BSS returns major-unit USD numbers (minor units NOT DOCUMENTED): 2 digits assumed, hourly price of flavor + system volume rounded **up**. A flavor/region the price API cannot price has no price ⇒ never offered. Pay-per-use only (`cond:operation:charge`)                                                                                                                                                                                                                                                                                                                                                                         |
| SSH keys                   | cloud-init `user_data` (documented field); key-pair APIs were not read — NOT VERIFIED that every image honours it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| billing                    | usage details, `consume_amount` rounded to 2 decimals, `providerRef` = `res_instance_id`; the `offset` semantics are only exemplified (NOT VERIFIED)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

Not provided by the docs (so not done): VPC/subnet/security-group creation (networking is **configuration**: `network(regionId)`; without it provisioning is rejected); Windows images (can no longer be used to create ECSs); flavor availability per AZ for pay-per-use beyond `os_extra_specs`; me-east-1-specific flavors, AZs or prices; CBR backups; numeric ECS/IAM/CES rate limits (only the gateway default 200/s and the BSS table).

## Least-privilege IAM (as documented; two models exist and use different prefixes)

`ecs:cloudServers:createServers`, `:listServersDetails`, `:showServer`, `:start`, `:stop`, `:reboot`, `:resize`, `:deleteServers`, `ecs:cloudServerFlavors:get`, `ims:images:list`, `ces:metricData:list`, `evs:snapshots:create` + `evs:volumes:get` (the action for `/v2/{project_id}/cloudsnapshots` is NOT DOCUMENTED), billing `billing:billDetail:view` and `billing:contract:viewDiscount` (policy-based model: `bss:billDetail:view`, `bss:discount:view`), IAM `iam:projects:listProjects`; Create also needs EIP/VPC dependencies (`eip:publicIps:create`, `eip:publicIps:associateInstance`, `eip:bandwidths:insertPublicIps`, `iam:agencies:pass`). The permission for the job query (`GET /v1/{project_id}/jobs/{id}`) is NOT DOCUMENTED.
